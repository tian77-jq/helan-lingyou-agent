# 提交分包说明（V26.0 §九）

本文件解释**两个交付包**的用途、结构与约束，并说明赛事规则与 WorkBuddy 插件规范之间
一处已知冲突的处置方式。

---

## 一、为什么分两个包

| 包 | 用途 | 是否参赛主作品 | 是否必需 |
|---|---|---|---|
| **Web 主工程包** `SilverCup-Agent-Web-<git-sha>.zip` | 《贺兰有灵·灵游宁夏》独立 Web 应用（React + FastAPI + 六 Agent 业务核心） | ✅ 是 | ✅ 必交 |
| **WorkBuddy 原生扩展包** `helan-lingyou-ningxia.zip` | WorkBuddy 专家团插件（六 Agent 原生角色） | ❌ 否（能力资产） | 可选 |

**关键关系**：两包**共用同一套业务核心**（`domain/helan_agent/`），但**互不依赖**——
评委不安装专家团，也能完整运行 Web 主作品；安装专家团只是让平台内多一条原生入口。

---

## 二、已知冲突与处置（重要）

> **冲突**：赛事提交规则要求「**排除隐藏文件**」；
> 而 WorkBuddy 官方专家团规范要求插件**必须包含** `.codebuddy-plugin/plugin.json`（位于隐藏目录）。

官方要求（实取 <https://open.workbuddy.cn/docs/expert-team>）：

```
my-team/
├── .codebuddy-plugin/
│   └── plugin.json              # ★ 配置文件（必须）
├── avatars/                     # ★ 头像目录（必须）
├── agents/                      # ★ Agent 定义（必须）
├── skills/                      #    共享技能（可选）
├── settings.json                # ★ 设置主理人（必须）
└── README.md
```

**处置：清晰分包，而不是删文件。**

| 包 | 隐藏目录处理 |
|---|---|
| Web 主工程包 | **不含**任何隐藏目录（`.git`、`.workbuddy` 等均已排除），满足「排除隐藏文件」 |
| WorkBuddy 原生扩展包 | **必须保留** `.codebuddy-plugin/`，并在包内 README 标注为必需文件 |

> 绝不因「排除隐藏文件」而删除 `.codebuddy-plugin/plugin.json` —— 那会导致插件无法加载。

## 三、Web 主工程包结构

解压后根目录为 `SilverCup-Agent/`：

```
SilverCup-Agent/
├── preflight.cmd / start.cmd / verify.cmd   # Windows 一键入口（跨设备，无盘符硬编码）

├── domain/helan_agent/                      # 六 Agent 业务核心（纯标准库）

│   ├── corpus/                              # 文化/生态/景点语料
│   └── qa_engine.py / evidence_gate.py / retriever.py
├── web/                                     # FastAPI 后端 + React 前端
│   ├── app.py                               # 后端（经统一 AgentRuntime）
│   └── frontend/{src,dist}/                 # 源码 + 已构建产物（免 npm 构建）
├── mcp-adapter/server.py                    # 本地 stdio MCP 服务（WorkBuddy 复现入口）
├── evaluation/                              # 40 例回归 + 六场景用例
```

**排除项**（构建时自动排除，实测确认）：`.git/`、`node_modules/`、`__pycache__/`、
`.venv/`、`.workbuddy/`、`.env`、`evidence/acceptance|agent_execution`、
`evaluation/results/`、`submission/06-evidence|08-final-package`、`*.log`。

**保留项（有意为之）**：`web/frontend/dist/` —— 已构建前端，评委无需 `npm install` 即可
由后端直接托管；如需改前端再执行 `npm install && npm run build`。

## 五、录制视频的版本一致性

演示视频必须在源码包中**可实际复现**：

1. 视频录制所用代码版本 = 包内 `git` SHA（见包名与 `submission/manifest`）。
2. 视频中出现的功能，均可用包内命令复现：
   `start.cmd` → 浏览器 `http://127.0.0.1:8080` → 输入视频同款需求。
3. 视频中如展示"实时天气"，需网络可达；不可达时界面会**如实标注"待核实"**
   （这是设计行为，不是缺陷）。
4. 不录制任何未在源码中实现的功能。
