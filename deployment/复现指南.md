## 8. V21.0 运行时版本自证与六态门禁（判断是否"真正生效"）

> 核心原则：**不得以注册成功、`installed_plugins.json` 指向新版、或"重新召唤"成功推断版本已生效。**
> 必须以 §5 ① 的 `cli.py --version` 运行时输出为唯一权威判据。

### 8.1 为什么需要运行时自证（官方更新语义）

依据官方 `workbuddy.cn/docs/cli/plugin-marketplaces` 文档原文：

- 版本化缓存**不可变**：`plugin update` 声明版本与已安装版本相同 → 视为 up-to-date，**不重写 cache/registry**；
- 版本变化时写入**新版本目录**并**原子切换 registry**；
- **旧 Session 继续引用旧目录**（运行中会话不拾取新版本）；
- 首轮投影 cache-first（只读 `enabledPlugins` + `installed_plugins.json` + 指向的不可变 cache，不扫描 Marketplace）。
- **结论**：任何包内容变更（引擎/语料/提示词/SKILL）一律**递增版本号**；版本号不变的内容变更永远不会到达运行时。

### 8.2 可追溯版本清单（来自实际文件/程序，不靠复述）

| 维度 | 来源 | 说明 |
|---|---|---|
| Git SHA | `git rev-parse HEAD`（仓库工作树） | 开发事实源 |
| 插件 version | 包内 `.codebuddy-plugin/plugin.json` / 市场源同款 | 发布版本号 |
| 包 SHA-256 | `sha256(zip)`（`release_record_*.json` 记录） | 分发完整性 |
| 六 Agent 定义哈希 | `agents/*.md` + SKILL.md | 提示词基线 |
| 随包引擎+语料哈希 | `release-manifest.json`（构建期）= `cli.py --version`（运行时）= `sync_check.py §5.1`（自检期），**三处同口径**（`sha256 over sorted 'relpath\0sha256\n' lines`） | 引擎真实内容指纹 |
| 实际加载插件路径 | `installed_plugins.json` → `cache/.../<version>/` | 运行时来源目录 |
| 实际执行业务入口 | 包内 `skills/helan-knowledge-qa/scripts/helan_agent/cli.py` | `engine_root` 即证据 |

## 9. 受控发布流程（开发→正式专家团，V21.0 固化脚本）

> 每次 Hy3 完成开发，用一条命令把"源码变更同步进正式专家团"的前三步固化，杜绝凭感觉发布。

### 9.1 命令

```bash
python scripts/release_expert.py --version 1.2.5            # 正常发布（版本须严格大于市场源）
python scripts/release_expert.py --version 1.2.5 --dry-run  # 只检查不落盘
python scripts/release_expert.py --version 1.2.5 --skip-regression  # 已另行跑过 40 例回归时
```

### 9.2 六条硬规则（违反即中止）

| 规则 | 含义 |
|---|---|
| R1 版本递增 | 目标版本必须严格大于市场源当前版本（同版本=不重写缓存） |
| R2 不覆盖缓存 | 目标版本目录已存在于安装缓存则拒绝（版本化缓存不可变） |
| R3 官方校验 | 发布前必须过官方 `validate_expert.py`（含 team 类型必需的 settings.json） |
| R4 解压复检 | zip 必须复检：清单在位、引擎/语料哈希一致、settings.json 在位、版本号正确 |
| R5 不碰安装缓存 | 只写市场源与 submission 快照/分发包，**绝不触碰安装缓存** |
| R6 工作树干净 | 未提交变更会被游客会话拾取且使版本不可追溯（确需发布用 `--allow-dirty` 留痕） |

### 9.3 流程

1. 同步引擎/语料到市场源技能目录（`sync_engine_to_market`）；
2. 生成 `release-manifest.json`（引擎+语料组合哈希，与运行时/自检同口径）；
3. R-3 对策：市场源根 `settings.json` 缺失则从 submission 快照恢复（team 类型 validate 必需，平台预览流程会清它）；
4. 升市场源 `plugin.json` 版本号；
5. 官方 `validate_expert.py` → 官方 `package_expert.py` 打包；
6. 解压复检 + 同步 submission 快照；产出 `release_record_*.json`。

### 9.4 三项"必须失败"检查（证明机制有效，不是摆设）

- **随包引擎漂移**：仓库 `domain/helan_agent` 与包内引擎组合哈希不一致 → 发布检查失败（源码改了但随包引擎没同步，禁止发布）；
- **发布清单缺失/MISMATCH**：包内 `release-manifest.json` 不存在或哈希与实时引擎不一致 → 失败；
- **同版本内容差异**：市场源版本号 == 缓存版本号但逐文件内容不同 → 明确判定 `SAME_VERSION_CONTENT_DIFF`，强制升级版本号（杜绝"改了内容不升版本"）。

> 实证：V21.0 自检脚本在发布前曾检出「引擎 DRIFT / 清单缺失 / 同版本内容差异」三项（见 `06-evidence/version_sync_20261016_074510.md` 与更早的 `b1757bf` 提交记录），确认检查真实拦截而非空转。
