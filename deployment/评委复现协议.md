| 类别 | 包含功能 | 评委如何验证 | 当前状态与证据 |

| **② 已实际验证的公开 HTTP 数据源** | A4 天气查询（Open-Meteo，公开免密钥） | 第 10 步天气区块显示真实来源与时间戳；预检第 10 项可达性探测 | ✅ 已交付（本机网络可达时）。出网受限时**如实降级**为「待核实」，不伪造数据 |

### 1.3 三条如实性禁令（本工程对自身的约束，也是评委核对口径）

> 1. **不得**把 `model_calls=0` 的确定性执行业务描述为"真实大模型推理"。当前 A1–A5 是「确定性业务核心 + 真实工具调用（A1/A2 BM25 检索、A4 真实 HTTP 天气）」；只有评委自行配置 `HELAN_LLM_*` 后才发生真实模型请求，且模型只许改写表述、不得新增无来源事实。
> 2. **不得**把「MCP 工具已经存在并可本地调用」描述为「平台专家团已经完成调度」。工具存在 ≠ 成员注册运行；后者属平台侧人工步骤，状态 `PENDING`。
> 3. **不得**把同程、地图、交通、门票、住宿等尚未完成授权的服务标注为"已接通"。此类能力在审计报告中的结论就是未实现/未授权，交付物中不得出现相反表述。

### 1.4 账号隔离与双模式（新账号复现边界）

- **新账号不继承旧账号资产**：本工程在开发者账号下取得的证据（已安装的专家团 `helan-lingyou-ningxia`、平台侧 MCP 信任记录、市场源缓存）**不会**随源码迁移到评委账号。评委在新账号/新设备上必须按第 12 步自行完成平台侧动作。
- **账号级配置给人工步骤，不伪称随源码迁移**：随源码交付的只有 `mcp-adapter/server.py`、专家团打包文件（`submission/07-deployment/helan-lingyou-ningxia.zip`）与提示词/Agent 配置；"在客户端添加 MCP Server""分配工具权限""安装/更新专家团"三项恒为人工步骤，仓库不得代声明已完成。
- **双模式**：① **本地 Web 模式**（第 1–15 步，无需任何平台账号，全程本机复现）；② **WorkBuddy 平台模式**（第 12 步 + §3，需要平台侧人工动作）。两模式共用同一业务核心（`domain/helan_agent/`），结果语义一致。

## 2. 十五步复现流程

> 以下所有命令在**工程根目录**（下称 `<工程根>`）执行。Windows 一键脚本内部优先使用 `py -3`，找不到时回退 `python`，与本文命令等价。

### 第 1 步 · 下载、解压与目录确认

```bat
:: 解压提交的分发包，得到工程根目录（下称 <工程根>）
:: 分发包名示例：SilverCup-Agent-Web-c36c370.zip（以 submission/08-final-package/ 实际文件与 §6 SHA-256 为准）
cd <工程根>
dir
```

应看到：`install.cmd` / `start.cmd` / `stop.cmd` / `preflight.cmd` / `verify.cmd` / `requirements-web.txt` / `.env.example` / `AGENTS.md`、`web/`、`domain/`、`mcp-adapter/`、`evaluation/`、`submission/` 等目录，以及 `SilverCup-Agent-web/`（内嵌 B 工程副本）。

包内**不含**：`.git`、`node_modules`、`.env`、`.tmp-*`、两份官方 DOCX 模板、本地草稿目录（由 `tests/test_submission_packaging.py` 17 项规则测试保证）。

### 第 2 步 · 环境预检

```bat
preflight.cmd
:: 等价于：python scripts/launch.py preflight
```

覆盖 12 项：Python 版本、工程完整性、语料可读、共享核心可导入、Web 依赖、Node（可选）、端口、写权限、外部数据源可达性、模型端点配置、跨设备硬编码自审。
**退出码 0 = 无阻塞；1 = 有阻塞项**，按报告「修复」列处理（预检 BLOCK 不阻止继续安装，`install.cmd` 会警告后继续）。

```bat
:: Windows 激活：.venv\Scripts\activate      Linux/macOS：source .venv/bin/activate
```

一键方式：双击 `install.cmd`（内部 `launch.py setup` 自动完成第 3、4 步）。

> `install.cmd --build` 或 `cd web/frontend && npm ci && npm run build && cd ../..`

### 第 5 步 · 配置（可选；不配置则走确定性引擎）

```bat
copy .env.example .env
:: 然后按注释填写。留空全部可选项 = 无密钥确定性运行，无需联网、无需付费
```

按 §1.2 四类能力对号入座：**第①类不需要任何配置**；第②类不需要密钥；第③类在此填写（`HELAN_LLM_*` / `HELAN_PEXELS_API_KEY` / `HELAN_UNSPLASH_ACCESS_KEY`）；第④类**填了也不会接通**（产品侧未闭合）。

也可直接用本机环境变量（与 `.env` 等价）：

```bat
set HELAN_AGENT_MODE=auto                 :: auto | model | deterministic
set HELAN_LLM_PROVIDER=openai_compatible  :: 任意 OpenAI 兼容端点
set HELAN_LLM_BASE_URL=https://api.deepseek.com   :: 以 Provider 官方文档为准
set HELAN_LLM_API_KEY=<评委自己的密钥>
set HELAN_LLM_MODEL=deepseek-chat        :: 以 Provider 官方模型标识为准（V32.2 开发账号实测此标识成功）
set WEB_PORT=8080                         :: 端口被占用时改此值
```

> 安全边界：密钥只进环境变量/`.env`；`.env` 已被 `.gitignore` 排除，**不入包、不入库、不下发前端**。
> `HELAN_AGENT_MODE=model` 但缺端点配置时系统判 `BLOCKED`，**不静默降级**（如实性设计）。
> 图片 Key 只进后端：`domain/helan_agent/image_service.py` 适配层按五级优先级获取，未配置即上报 `NEEDS_AUTH` 且不发起请求；Wikimedia 免 Key（网络不可达时如实上报 `NETWORK_BLOCKED`）。

### 第 6 步 · 启动服务

```bat

:: 等价于：python scripts/launch.py start
:: 如需就绪后自动开浏览器 + 真实探测 /health 与关键 API：

```

`launch.py start` 优先使用 `.venv` 解释器；缺 fastapi/uvicorn 时提示并尝试自动安装。端口占用时按提示执行 `stop.cmd`（第 13 步）或改 `WEB_PORT`。

### 第 7 步 · 浏览器访问首页

浏览器打开 `http://127.0.0.1:8080`（后端直接托管已构建前端）。

应看到：对话输入区、行程看板、门禁与审核区、来源引用区。**页面不得空白**（空白 = `dist` 缺失或未构建，见第 14 步排错）。

### 第 8 步 · 健康检查

```bat
curl -s --noproxy * http://127.0.0.1:8080/health
curl -s --noproxy * http://127.0.0.1:8080/api/capability
```

- `/health` 应返回 `status=ok`，并标注「本地共享核心执行，非 WorkBuddy 云端 Agent 执行」。
- `/api/capability` 显示当前**真实**执行模式（`execution_mode`、未配置模型时的原因、`image_providers` 各源状态）。这是核对 §1.2 第③类的唯一权威字段——**不得凭界面印象判断**。
- `curl` 访问本机务必 `--noproxy *`（或设置 `NO_PROXY=127.0.0.1,localhost`），否则可能被本机代理转发导致误判失败。

### 第 9 步 · API 验证（无浏览器亦可复核）

```bat
curl -s --noproxy * -X POST http://127.0.0.1:8080/api/chat -H "Content-Type: application/json" ^
  -d "{\"session_id\":\"judge\",\"message\":\"一家四口去宁夏玩三天，预算5000元，想了解贺兰山文化，安排住宿/交通/美食/亲子研学，不要太累。\"}"
curl -s --noproxy * http://127.0.0.1:8080/api/session/judge
curl -s --noproxy * http://127.0.0.1:8080/api/trace/judge
```

- `/api/trace/{sid}`：统一执行轨迹（`helan.execution_trace/1.0`），含 12 字段消息流（A0→Ai `DISPATCH` / Ai→A0 `RESULT`）、DAG 校验、任务账本、工具证据、A5 裁决、三道门禁、7 项一致性自检。
- `/api/reset`（POST）：重置会话；`/api/content`（POST）：内容创作。

### 第 10 步 · 典型任务：与演示视频一致的三日游需求

在对话框第 1 轮输入（与演示视频、40 例回归场景一致）：

```
一家四口去宁夏玩三天，预算5000元，想了解贺兰山文化，安排住宿/交通/美食/亲子研学，不要太累。
```

应观察到（缺一即对照第 14 步排错）：

| 观察点 | 预期 |
|---|---|
| 行程结构 | 按天/城市/景点完整排布，含住宿/交通/美食/亲子研学，强度符合"不要太累" |
| 天气 | 真实来源 + 时间戳（Open-Meteo）；出网受限时**如实**显示「待核实」而非假数据 |
| 文化引用 | 每条文化事实带来源与核验状态；内部资料标注「内部资料，外部来源待核实」；争议事实（如岩画断代）带限定语 |
| A5 审核 | 审核提示与裁决可见 |
| 三道门禁 | `publish_policy` / 文化证据充分性 / 行程可发布 四层语义**独立呈现**，不得合并成一个"通过" |
| 预算 | 5000 元口径一致，超支有显式说明 |

第 2 轮输入（验证状态继承与局部重规划）：

```
第二天我还想去沙坡头，尽量不超预算。
```

应观察到：`state_version` 递增；`user_constraints` 保留第 1 轮的 3 天 / 5000 元 / 4 人 / 低强度；第 2 天重排入沙坡头并给出跨城交通与预算影响；被置换景点进入「备选景点」并显式告知（**不得静默丢弃**）。

### 第 11 步 · 历史产物功能验证（V32 新增）

在同一会话中完成**至少两轮"新规划"类请求**（例如第 10 步的三日游之后，再输入"改成两人两天，预算3000"这类会触发重新编排的需求）：

- 界面出现「历史产物（查看所有产物）」入口（仅当本轮会话产物数 > 1 时显示），标注"共 N 个产物"；
- 点击可回看本会话此前生成的路书版本（"第 N 版 · <标签>"），当前版本高亮；
- **只对轮次真实重排生成产物**（`itinerary_origin=this_run`），不伪造历史版本；
- 文化问答等非规划类请求**不生成**新产物，但保留上次行程可查看；
- `POST /api/reset` 重置后产物清空（对应前端测试"重置后清空（不伪造历史）"）。

> 该功能为**会话级前端状态**，不落盘、不跨会话；复现重点在"多轮规划后可回看旧版本且版本计数真实"。

### 第 12 步 · MCP 入口与专家团（WorkBuddy 平台侧）

```bat

:: 引擎 + HTTP + 本机 stdio MCP 三路实测，输出双门禁报告
```

业务核心经 `mcp-adapter/server.py`（本地 stdio MCP Server，JSON-RPC 2.0）暴露 **12 个工具**：

### 第 14 步 · 排错（故障识别清单）

| 现象 | 原因 | 处理 |
|------|------|------|
| `/health` 返回 `execution_mode=deterministic` | 未配置模型端点（**属正常默认**，不是故障） | 如需模型执行，按第 5 步配置；不影响 Web 功能与门禁 |
| `/health` 连接被拒 / 超时 | 服务未起来；或本机代理转发了 127.0.0.1 | `curl --noproxy *`；设 `NO_PROXY=127.0.0.1,localhost` |
| 预检报 `BLOCK: Web 后端依赖` | 未装 fastapi/uvicorn | 第 4 步安装依赖 |
| 8080 被占用 | 端口冲突 | `stop.cmd` 释放，或 `set WEB_PORT=8090` 后重启 |
| 前端页面空白 | `dist/` 缺失或损坏 | 确认包内 `web/frontend/dist/index.html` 存在；否则第 4 步重建前端 |
| 天气显示「待核实」 | 出网受限或上游不可达 | **诚实降级设计**；放通 `api.open-meteo.com` 即恢复。**不得**据此判定产品缺陷 |
| 图片区域为空 / 标注 NEEDS_AUTH | 未配置 Pexels/Unsplash Key 或 Wikimedia 不可达 | 第③类能力；未配置时如实上报，不伪造图片 |
| 界面无「历史产物」入口 | 本会话只发生过一轮规划 | 先完成两轮"新规划"类请求（第 11 步） |
| 六场景中 D/E 显示 SKIPPED | 该场景需故障注入，只在引擎入口运行 | 预期行为（不伪造通过），见 §4 |
| MCP 场景在 Web 入口 SKIPPED | 场景归属设计 | 同上 |

### 第 15 步 · 清理与重新复现


## 3. WorkBuddy 侧复现细节（同一业务核心的第二入口）

工程提供 `mcp-adapter/server.py`（本地 stdio MCP Server，JSON-RPC 2.0），把共享业务核心暴露为 12 个工具（清单见第 12 步）。三个入口（Web / MCP / CLI）**全部经统一 `AgentRuntime`**（`domain/helan_agent/multiagent/runtime.py`），业务实现只有一份，改业务只改 runtime，不存在多份漂移实现。

「一致」的判定口径见 §4。场景归属说明：六场景 A–F 中，D（天气不可用降级）与 E（上游缺陷阻断发布）需**故障注入**，只在引擎入口执行；Web/MCP 入口对这两场景**显式记录 SKIPPED + 理由**，不伪造通过。

---

## 4. 「一致」的判定口径

一致 = **功能、约束、执行路径与结果语义一致**，不要求：

- 动态天气 / 地图查询结果逐字相同（受实时数据与授权影响）；
- 大模型措辞逐字相同（措辞可变，事实与来源必须一致）。

即：两入口必须给出**相同的行程结构语义（天数 / 城市 / 景点集合 / 预算口径 / 约束继承行为）**、**相同的门禁结论口径**、以及**同一逻辑格式的执行轨迹**（`helan.execution_trace/1.0`）。
